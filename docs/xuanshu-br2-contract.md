# BR-2 验证专用发送保护

2026-11-05，实施前增量规格。BR1-KI-001按用户接受的非阻断遗留保留，不重复定位。

## 已有能力与增量

复用Service唯一worker、RPC验证计数/事件账本、发送前检查、完整预览和原逐任务可信确认。新增独立BR-2启用接口和策略解析；不改变旧公开结构、错误值、DDL或RPCB批次合同，不新增Provider或执行器。

策略只能由可信宿主初始化提供，普通页面/模型/工具输出不能启用或修改。启用本身不授予确认资格。BR-2模式只能接纳一个固定浏览器只读任务，history=[]，browser.view，browser.snapshot，state/revision；拒绝另建任务和继续提案。重复相同client仅返回原任务，不重置预算。原普通任务不改变。

## 发送及重启

每次初始/续轮传输必须在唯一worker内先持久化额度占用，再在传输边界核对request/run/body身份和已占用ticket。累计最多3次，占用不退款，不自动重试。第4次在传输前拒绝。占用、传输入口、完整响应、远端未知分别记录，不宣称精确HTTP次数。

现有events账本记录BR-2策略身份、价格依据与占用/费用，无DDL变化。旧库存在任务或保护事件时只恢复计数和记录并锁停；不恢复授权、不自动请求。存储失败或不完整状态禁止发送。相同库的独占存储锁防止并发Service取得独立可写预算。删除/换库不是继续同一验证，不在自动启动/重试路径中。

## 期限与费用

可信逐任务确认成功起单调时钟10分钟；每个发送前及运行期检查。到期禁止后继并按既有取消/回调/关闭合同收尾，不提高网络超时，不保证远端停止。

USD0.10=100000000 nano USD。策略绑定model、固定deepseek-responses-v1、价格版本/依据和每请求可计费input token可靠上界；output固定4096。发送前保守预留为input上界×单价+4096×输出单价，不能用请求字节数冒充token上界。上界必须含协议隐藏开销，依据未确认、无法匹配或不够可靠时不允许真实启动。替身测试的已知计费上界不等于真实服务证据。

usage完整且在策略界限内才记known（依绑定价计算，非账户账单）；发送前预留为estimated；usage缺失、超界或远端未定为unknown，不能记0，停止后继。本地估算不承诺服务端绝对扣费上限。价格策略只读绑定，不能靠页面消息扩大。

## 自审收紧与计数边界

策略必须携带与Service storage_path逐字一致的database_path_utf8；复制同一批准策略到另一新库会锁停，不能复用预算。当前交付入口只接受unverified模板，派生本次库绑定策略；它不是实际调用启动器。未来授权必须先创建唯一隔离库路径并将其写入一次批准策略，不能重新派生新库续跑。同库遗漏策略参数重开仍自动识别BR-2账本并锁停。

新限制接口是独立增量，不改旧公开结构。新提案在比较固定目标之前检查所有内嵌字符串终止符及v1精确read scope，防止畸形重复请求绕过原校验边界。

provider_request manifest可能在额度判断之前持久化；第4次可有第4份候选请求记录，但不能有第4次额度占用或传输入口。不得将manifest、model_calls、ordinal直接当作HTTP次数。失败的reservation写入不返还内存占用，但不能声称失败记录已持久化；Service会锁停，已有BR-2开启记录阻止重启派发。

启动监督沿用原8项验证设计；本轮只扩展本地Proposed策略绑定及环境恢复，辅助进程验证与真实宿主启动分开标注。BR1-KI-001未解决，当前被接受为非阻断，出现实际差异立即停对应任务。
