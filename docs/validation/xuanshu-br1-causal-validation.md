## 源码约束与候选排除范围

1. 原失败归档的 text 与当前 helper 都通过一个 UI_INPUT_TEXT 提交完整字符串，不是逐字符输入。`lw_text_replace`在UTF-8转换后一次strcpy写入value。因此“原夹具最后一个字符仍在自己的字符队列中”不符合原调用链，不能作为根因。
2. Light输入整串替换、同值替换、焦点转移、重复投影和普通字符队列在本次明确序列中都保持全文。不能据此排除未覆盖的原生编辑事件组合。
3. 页面只有输入为空且配置有模型时初始化模型框；普通非空状态投影不会按长度截断。保存按钮读取value，桥接JSON序列化，宿主read_string逐字复制，configure按127字节上限验证后整串复制；本次wire/answer/configure/读回逐值一致。
4. configure以job/busy和锁保护pending_model，worker用字符串复制序列化及读回。旧任务取自己的绑定。未找到把15字节正常ASCII有意改为14字节的分支；这不是对所有内存错误的证明，也不把原错误归因环境。
