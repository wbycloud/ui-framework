# API7 真实业务试点准备

本轮交付准备方案。尚未指定本轮API7试点业务应用，也没有应用接入修改授权；此前 KLayout 的授权只允许只读菜单观察，不延伸为迁移授权。框架测试 DLL/.uapp 的通过属于集成证据，不能填写为本表的业务通过。

## 1. 启动条件和最小范围

请求方需明确应用仓库/包及基线 commit、允许修改的接入目录、测试数据和保存位置、试点负责人、运行后端及退出/回退方式。只读盘点可先做，代码接入在授权明确后开始。原包、冻结 SDK、业务模型/算法/格式和 PERF-001 保留；先在应用自身允许的试点分支建立基线，实际提交与包 SHA256 逐项记录。

锁定可取得的 API7 框架 commit，核对 CMake 0.7.0、API7/标准7、ABI1/包格式1。当前本地提交尚未发布，不能仅从 main 获取后假定匹配。参见[迁移](migration-v0.6-to-v0.7.md)、[开发标准](application-development-standard.md)、[构建及 CI](build-and-validation.md)、[本轮证据](validation/api7-delivery-validation.md)。

最小试点选一个只读大数据浏览窗口、一组可撤销属性、一个现有 GL 内容槽、一个异步缩略图 source、一个实例模态对话框及两个同时打开的文档。业务存储/排序/撤销仍由应用负责；本轮不扩展模型、任意分割树、富文本或硬件无窗口 GL。

## 2. 接入检查表

| 检查项 | 接入责任与可观察结果 |
| --- | --- |
| C ABI/包 | DLL 链接匹配的共享运行库导入库；descriptor 与八字段清单一致。结构清零后设置 size，只读写完整字段，旧偏移/枚举不变；应用保存 SDK commit |
| 大表/树 | 使用完整 source 的 total_count、稳定非零 uint64 ID；JSON 用十进制字符串。至少十万行和实际宽表，排序由全数据 source 执行，范围选择返回真实稳定 ID，不能排缓存或预载全量 |
| 属性/颜色 | 公共字段、枚举 options、RGBA/透明度及文本草稿；Enter/提交一次、Esc/取消恢复；业务校验/事务成功后 accept_fields，回填不再次提交 |
| 布局 | 稳定面板 ID；注册/mount 后恢复，应用按用户/实例存不透明格式2并备份格式1。未来/异常文件检查返回并提供 reset；底部/同区标签沿原槽和 GL context，不重 mount |
| GL | 保留业务 frame/input/resize 与资源；可选 OSMesa 时全部 GL 函数由 surface 解析、显式绝对提供方路径，实际查询 NO_WINDOW/samples。隐藏 WGL 与 OSMesa 分别声明 |
| 图片/异步 | RGBA 输入顶向下非预乘且返回前复制；按所有权 update/release。worker 保存实例/代次/项目/版本/请求/DPI，复制投递；迟到结果不进入新实例，缩略图由业务实际 renderer 产生 |
| Runtime | 实际 WebView2 SDK/Runtime、STA 消息循环和 framework_components；后端借用寿命到 host 清理，PENDING 需真实完成后重试，不保留输出缓冲地址 |
| 生命周期 | REFUSE/WAIT；停止新工作、join worker、撤销订阅、释放应用 GL/回调，全部调用退出后卸载。初始化 create/mount 部分失败沿同一清理路径；框架 Runtime 后续关闭仍由 UI 线程推进 |
| 预算 | DOM1024、缓存2MiB、单批512、列/字段64、图片32MiB、投递/JS各8MiB不提高；多选512。业务数据存储不混入框架缓存统计 |

## 3. 可复验操作与成功标准

授权接入后，在匹配框架宿主中打开应用包。不要把业务包传给 `ui_api7_integration_test`：该运行器依赖框架 fixture 的命令/面板合同，不能驱动任意业务包。应用需按自身命令建立最小回归驱动或记录人工步骤。

```powershell
# 在 x64 开发终端；路径由请求方指定，不覆盖原包。
& .\build\web-shell\framework_host.exe <试点应用.uapp> <试点应用.uapp>
```

| 顺序 | 操作与成功标准 |
| --- | --- |
| 1 | 记录应用/框架 commit、DLL/.uapp/运行库/依赖哈希、OS/Session/DPI/Runtime/GL info。基线业务文件哈希与工作区差异可核对；原包只读 |
| 2 | 打开两个实例、交替切换，编辑草稿/选择/滚动/布局互不影响；菜单、快捷键及语义命令记录次数，一次手势一次命令 |
| 3 | 对十万行拖到首/末行、宽表首/末列，展开/折叠树；记录 source 查询范围、total 与 DOM/cache。无溢出隐藏，分页/键盘仍可到末项，ID 不变且原预算内 |
| 4 | 排序/换源/总量缩小时继续拖动，故意投递上一代结果；旧结果 CANCELLED/丢弃，显示新全数据顺序，不覆盖有效草稿/选择；范围选择结果按完成时机检查 |
| 5 | 枚举、合法/非法颜色、透明度、表格编辑提交/取消、只读/禁用；非法提交没有业务命令，合法提交一次并经业务校验回填；取消不保存业务修改 |
| 6 | 保存布局、重开恢复；底部/标签、关闭活动页/激活、拖拽/分隔条提交与 Esc 取消。尝试格式1、未来版本、截断/重复ID、增减面板和窄窗/reset；异常恢复不部分应用，所有面板可达 |
| 7 | 带草稿/选择时停靠、标签切换、resize/DPI逻辑变化；原内容槽/组件及 GL context 身份保持，业务实际 frame 可见且输入/尺寸正确 |
| 8 | 缩略图真实后台生成、C图片 update/release；模态期间阻止目标实例背景输入，另一实例独立；关闭模态恢复有效焦点；迟到图片不复活已释放资源 |
| 9 | create/mount 失败、任务运行中 WAIT、关闭/重开、DLL卸载；记录 worker/callback 出栈、模块卸载、pending cleanup 和 Runtime 进程资源，不以 flush 空闲或 browser 消失代替回收 |
| 10 | 两个 Web 后端分别重复独立进程及连续周期（快速与实际呈现后关闭）。保留资源基线/峰值/终值和每次失败，不清理 Runtime 用户目录或强杀进程；沿框架原句柄+12、GDI/USER+4基线用例复验，业务自有资源另按事先声明的生命周期核对 |

各项附操作输入、预期/实际、日志或截图、失败及修复 commit，回归后仍保留原失败。真实业务输出必须来自业务 renderer，框架三角形/Fixture 图片不替代业务输出。试点成功要求上述所选业务链路全部达到标准，两后端结果单列；仅编译、返回 UNSUPPORTED、模拟或框架 fixture 通过均不能通过试点。

## 4. 环境验收和结果模板

实际中文 IME 的组合/候选/提交取消、不同 DPI 物理显示器和屏幕边缘/DWM、长期人工压力另列操作记录。Session1、当前源码 Session0 和整机无登录是三项独立结论；只在有权限的服务环境执行现有[严格工作流](../.github/workflows/session0-osmesa.yml)。缺条件写待验，不注销用户、绕过权限或改既有服务。

试点记录最少包含：指定应用及授权范围、框架/应用 commit 与哈希、环境/依赖、各步骤输入和结果、资源曲线、原失败/修复复验、兼容/回退及未验条件。当前上述业务结果均为**未执行**。真实应用和修改授权明确后按这份清单推进，不把本轮准备文档称为业务验收完成。
