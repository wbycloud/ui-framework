# 正式只读助手页面方案

状态：Proposed，2026-11-04。方案及实现准备完成，尚未修改产品；等待确认日常使用方式。临时页面控件测试已取消，不属于本方案待补事项。

## 当前问题与复用范围

实际宿主host.html将主对话、问题回复、任务输入、stub脚本、配置、范围、技术详情、编辑和图诊断纵向叠放。用户需反复滚动定位，容易混淆编辑草稿与已接纳任务，以及本地保存与真实外发。这是日常信息组织问题，不意味着既有Service或授权架构需要重做。

沿用main.c、ai_panel.inc、ai_model_panel.inc、ai_projection.inc及同一Service。历史选择、资源/read目录及字段来自现有接口；任务固定目标和异步持久化查询保持。没有新执行器、第二主对话、默认外发或批次自动批准。

## 推荐页面结构

默认打开日常助手，主要区域仅显示会话/任务、当前内容、输入和当前任务状态。设置及开发诊断独立按需展开。现有侧栏方式优先保留；静态草图是信息结构示意，不承诺新的窗口系统或可拖拽布局。

```text
┌ 玄枢助手 ── [设置] [开发诊断] ┐
│ 会话与任务      当前选中任务    │
│ 任务A           等待范围确认   │
│ 任务B           已保存·未发送  │
│                 输入与回复     │
│                 [查看范围]     │
├───────────────────────────────┤
│ 新任务草稿                    │
│ 输入要完成的只读任务……        │
│ 范围：当前选择（不会自动发送）│
│ [选择范围] [保存任务并查看范围]│
└───────────────────────────────┘
```

空间不足时会话列表折叠为“任务记录”，不再挤入多列窄输入框。选中旧任务不覆盖当前草稿。已有任务的取消入口随任务状态展示；不把新任务保存按钮当成发送。

查看范围显示独立中文分区：本次输入、仅选中的历史、已接纳固定目标、只读能力/字段、模型和凭据状态、完整请求详情。技术epoch/hash保留在详情。草稿范围与固定范围明确标记，切标签不重新绑定已接纳任务。

完整请求详情保留原有界有序全文及实际读回确认门。详情收起时确认不可用；显示失败、旧代次、配置/目标变化、重建和关闭均撤销旧资格。不得用摘要代替原完整显示、页面自报或“看过”勾选框签发资格。

## 操作语义

| 操作 | 语义与约束 |
|---|---|
| 保存任务并查看范围 | 调用既有ai-model-propose，只接纳及持久化；成功后进入当前任务范围，失败保留草稿 |
| 确认并发送此任务 | 复用既有原生逐任务可信绑定，仅在完整展示和最终条件检查成功时可用；一次消费，不接受普通页面消息批准 |
| 请求取消 | 原任务取消入口，显示请求、终态及最终保存的区别；远端未知不写成已停止 |
| 设置 | 显示当前配置位置；未配置、保存中、失败、本地可读及服务端未验证分别展示；不自动取Key |
| 开发诊断 | 保留stub、受控编辑、图和命令诊断；默认折叠并提示用途，不删除或提升权限 |
| 复制诊断 | 既有脱敏复制，不授权、不提交、不读取密码框、不联网；失败不覆盖任务错误 |

按钮名称为建议文案，改变时同步测试选择器及说明；底层动作ID和可信绑定不因文案改变。

## 状态与边界

普通任务继续经过草稿、收到、持久化接纳、等待确认、排队/发送、流式/工具结果、终态、最终保存；界面只能展示已有证据支持的阶段。当前配置不冒充历史任务配置。重启恢复记录而不恢复旧授权，不自动提交或重放工具。

本方案不加入聊天内容自动选择、默认全历史、AI写入、新Provider、OAuth、跨实例共享写入、browser副作用或数据库迁移。SDK/API/ABI、C2/P4/P5、来源政策、预算、50ms脚本门及各资源上限保持。
