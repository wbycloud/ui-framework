## 1. 事实与范围

上轮用户没有看到可实际输入Key的界面；聊天“已录入”不能作为凭据保存证明。T1本地credential_unavailable、M1/R1/S0/C0/U0、工具0，唯一失败终态及正常退出已核对，不能归因为用户未配置、Key无效或DeepSeek拒绝。原根build/xuanshu-rpc-real-20261102-b5e731及其配额保持，不覆盖或退款。

源码确认：原验证窗口每15ms无条件SetWindowText，会重置选区；原凭据入口未分别保存弹窗结果、保存job、CredWrite、配置保存及读取错误，通用host_status又会被后续确认覆盖。原弹窗未出现的具体Windows返回原因仍未知，不能凭缺少诊断推定。先补受控回归，再修复已核实的入口/可观察性缺口。

随后原生控件受控回归进一步确认：原模型按钮拦截WM_LBUTTONUP后未做标准按钮的鼠标捕获/按下状态收尾，抬起后GetCapture仍为Key按钮。最小修复须在原输入资格已固定后、进入模态窗前释放该按钮自己的捕获并复位显示；不调用WM_COMMAND作为授权、不放宽原来源条件。此缺陷能干扰后续鼠标路由，但不能据此补造旧弹窗未记录的返回码或宣称它是旧现象的唯一原因。

本轮只改私有凭据UI/保存读取诊断、验证启动器和专用测试，不增公开授权接口。SDK0.10-dev/API10/标准10、ABI1/包1、旧公开布局/错误、只读/C2/P4/P5、数据库DDL、固定依赖和限额不变。

## 2. 原生入口与秘密所有权

原ui_ai_model_bind_button/light绑定及一次性可信输入消费保持。绑定失败明确投影错误；未绑定不能伪显示入口可用，不根据WM_COMMAND、source或应用声明打开Key窗口。程序注入及普通直接调用仍拒绝。窗口/保存不签发外发授权。

在原可信租约内使用框架原生模态Key窗口，标题/标签“设置DeepSeek API Key”/“DeepSeek API Key”，仅一个遮罩输入框及保存/取消，没有登录用户名猜测。无需读取已有凭据预填。输入沿用原ASCII可打印非空、最多512字符限制，不经过页面/日志/数据库/诊断；窗口控件和临时数组在取消/提交/错误后清空。引用仅按显式隔离配置路径派生，origin仍唯一DeepSeek。

模态窗口和外层方法租约覆盖重入、返回及后台交接。捕获打开前配置revision/binding，返回后重查关闭/目标配置/在途任务，条件变化不提交保存job；不禁止所有重入。关闭期间取消输入，等待方法退栈，不提前释放Service或窗口绑定。UI只等待用户输入的模态消息循环，不等待数据库、网络或worker。

## 3. 后台确认与脱敏状态

用户点击保存只代表提交；后台依次完成同ref的Windows凭据写入、模型配置持久保存、同ref本地读回校验，实际确认后才显示“保存成功，本地可读取；服务端未验证”。读取检查不发API，也不证明Key有效。失败或取消保持可观察，不能由聊天反馈、配置ready或点击代替确认。

ui_ai_model_get_state原JSON字段语义不变，ready仍仅为模型配置ready；增加credential诊断对象，不修改公开C结构。内容限定阶段、窗口已打开/提交、凭据写入/配置保存/本地可读取布尔、代次及各阶段系统错误码；未执行/未捕获的错误码为null而非0。凭据错误独立于host_status，后续任务确认不清除。错误码在失败点捕获，不附Key、Blob、认证头或任意系统内存。

阶段包括not_configured、prompting、cancelled、prompt_failed、saving、write_failed、config_failed、read_failed、readable、stale。具体名称为私有JSON诊断，不改变现有ui_status错误数值。新增私有字段与复制投影计入原配置对象/服务8MiB，不提高额度。

增加last_entry区分尚未收到、未合格输入、绑定已用、不可用及接纳，不将Windows合格分类称物理设备证明。已有请求路径本地读成功但本次进程未保存时标local_readable，不冒称保存成功；saved_revision与当前代次匹配才投影可用，新验证启动器还要求本轮written/config_saved确认。

生产网络读取仍只访问该ref，细化诊断但保留原credential_unavailable任务错误。验证启动器在本轮保存和本地读取确认前禁用任务入口；通用既有真实任务API及来源/外发合同不重新定义。启动/重开不偷偷枚举或读取其他凭据，不取环境Key。

## 4. 稳定诊断与复制

Key按钮、确认按钮的绑定代次及结果显式可见，未ready/保存失败不能指导用户填写不存在的输入框。操作步骤先确认真正出现Key窗口，再确认后台保存及本地读回，之后才允许T1外发确认。正式Light复用同一Service及相同凭据原生入口，不新增第二执行器。
